# Phase 2 residual boundary inventory

**Date:** 2026-09-18. **Scanned implementation commit:** `6643ebf7ffe37f71ade94b3dc717b5eb4c6baf2b`. This is the finite closeout audit and a decision backlog for the full package review, not a Phase 3 implementation plan. Dependencies below are observed; future ownership is explicitly a decision. The package remains one working Laravel/Filament installation with the existing User subclass integration.

## Reproducible scan

Run from the repository root against the implementation revision:

```sh
git rev-parse HEAD
rg --files src database resources stubs tests
rg -n -- '->(attach|detach|sync|save|delete|update|create|transaction)|::(create|destroy)|DB::|app\(.*::class\)->handle|authorize\(' src/Filament src/Http src/Models src/Support src/Actions database
rg -n 'use .*Filament|config\(|route\(|view\(' src database resources
rg -n 'MembershipNavigation|RegisterResponse|MembershipCandidates|CreateTeamForProgram' src tests
```

The final scan found 182 files, 93 mutation/check matches, 482 import/config/route/view matches and 49 extraction/navigation caller matches. The scan includes indirect support, HTTP, provider and seed callers, not just pages. Each match was classified below. Coverage paths name actual test files/groups; test results belong to the [implementation log](../change-logs/phase-2-bounded-hardening-closeout.md). They are not claims of a generated-app or browser exercise. Globs below are recursive when written `**`; exceptions are listed explicitly. The rows cover every file under `src`, `database`, `resources`, `stubs` and `tests`.

## Bounded mutation and dependency audit conclusion

The two known shared-behavior escapes are closed by CreateTeamForProgram and MembershipCandidates. No new mutation engine, policy ability, participant operation or event was introduced. The creation flow retains the actor-first lock sequence and same-connection transaction. There is no UI-owned database transaction after the extraction.

Remaining direct writes are in action/mutation kernels, invitation acceptance, latest-tenant middleware and database fixture seeders. The first group owns domain invariants; remembered-tenant saves are UI/session integration; fixture writes intentionally bypass runtime authorization/events. ProgramTeams' existing-link selected-record checks and MemberActions' policy-filtered labels are discovery/presentation checks followed by authoritative batches, not a second mutation engine. Per-email invitation loops preserve independent result/delivery contracts. Departure redirection and registration login happen after shared operations, with registration login explicitly deferred to outer commit.

No additional extraction is justified by this bounded scan. Full-package review did demonstrate two pre-existing bugs, now corrected as explicitly recorded bounded additions: stale InnoDB deletion graphs could silently omit removal hooks, and Program-only landing missed accessible memberships. Current pivot reads/validated cleanup and the existing Program panel fallback address those findings, with regressions in the concurrency and custom-panel suites. See the [review](../code-reviews/2026-09-18-phase-2-membership-package-review.md) for exact evidence. The review also assessed the documented registration payload, indirect mail/default-panel coupling, host policy/participant obligations and the actual locking diff. Open navigation/auth, retained-adapter, scaffold installer/config, User integration and reference-host questions are expected decisions for the separate Phase 3 plan. They are not authorization, atomicity or data-integrity fixes silently deferred from this closeout.
